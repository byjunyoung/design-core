What one screen file says

Short enough to read in a pull request. Everything a reviewer asks about is a key, and everything nobody decided is marked as such.
screen: order-list
section: "03. Orders - Order list"
type: list            # must have Empty · Loading · Error
platform: web

elements:
  - id: filter
    kind: filter-form
    fields: [period, branch, status]
  - id: table
    kind: table
    columns: [order_no, branch, amount, status]
  - id: paging
    kind: pagination

layout:
  root: { kind: stack, gap: space.lg, padding: space.xl }

states:
  Empty:
    - { target: table, replace: { kind: empty-notice,
                                  text: "No orders match." } }
    - { target: paging, hide: true }
  Loading:
    - { target: table, replace: { kind: skeleton, rows: 10 } }
  Error:
    - { target: table, replace: { kind: error-notice,
        text: { $tbd: { owner: pm, due: 2026-10-02 } } } }

flows:
  - { from: table, via: row, to: order-detail, nav: push }

refs:
  prd: notion:2a1f0d…
  task: github:acme/tasks#4155
type decides what must exist
A list screen without an Empty state is a lint failure, not an oversight found in QA.
elements are shallow
A kind and a few props. How a table looks is the component library's business, not the file's.
layout speaks in tokens
Never 16px. A design-system change re-themes every screen; a diff stays readable.
states are patches
Empty says what is different, which is exactly the reviewer's question. Variants (Create vs Edit) use the same shape.
$tbd is a value
Not an empty string. It has an owner, shows as a yellow dot in the picture, and blocks the canonical branch.
flows and refs are machine-readable
An arrow to a screen that does not exist fails lint. The spec and the ticket are one click away.
